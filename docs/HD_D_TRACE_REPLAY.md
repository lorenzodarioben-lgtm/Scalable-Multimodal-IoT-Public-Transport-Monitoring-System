# Final-D trace replay — offline sanity check only

**OFFLINE SANITY CHECK ONLY — NOT FINAL HD EVIDENCE.** This read-only replay did not call AWS, alter the D artifacts, or apply an HD recommendation to D capacity. Reproduce locally with `node experiments/hd/replay-d-trace.js`; machine-readable output is `experiments/hd/artifacts/d-trace-replay.json`.

Source: the single valid final-D **fast-reactive** replacement run `2026-09-22T10-51-14-826Z-incident-stage-1-autoscale-r1` in the original D checkout. The replay reads its `manifest.json`, `injection-timing.json`, `dispatches.jsonl` and `samples.jsonl` read-only. It retained exactly **630 unique submitted incident dispatches / 31,500 jobs** and grouped their actual dispatch-completion timestamps into **63 ten-second bins**. The D queue/ECS samples were held at the most recent recorded value for each bin; the largest such sample age was **28.147 s**. The frozen 8-sample/80-s controller was fed these recorded arrival-rate bins, sampled visible backlog and sampled desired/running tasks.

The recorded load was effectively flat at **50 jobs/s** once the bins filled. The D fast-reactive policy had already raised desired capacity to five around the period when the predictor first acquired eight bins. On this **observed D state**, the offline controller made **zero additional scale-out requests**. Its first full-history forecast was 50 jobs/s, and the recommendation was bounded by the already-requested reactive capacity. This is plausible: the predictor neither invented a rising trend nor tried to scale in below D's reactive floor. It does **not** establish that the HD predictor will or will not improve a different ramp-shaped workload.

Limitations are material. A dispatch's completion timestamp marks the last observed SQS batch completion, not each job's acceptance instant. D samples were approximately ten seconds apart and sometimes older; hold-last does not recover the intervening queue or task state. The visible/running quotient fed to the pure controller is **not genuine historical CloudWatch BPT** and is not used as a claimed metric result. Crucially, this is not a counterfactual simulation: the controller's proposed requests were not applied and the observed D ECS/task trajectory remained the fast-reactive one. No HD workload, reliability or AWS outcome can be inferred from this replay.
